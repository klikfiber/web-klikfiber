# KLIKFIBER audit — 23 September 2026

## Scope and dependency map (before changes)

Next.js App Router / React 19 / TypeScript. Root layout mounts a client Store which dispatches routes from pathname. Store imports workflows and portals; workflows imports Store context. Supabase owns customer authentication; custom hashed DB sessions own admin authentication. `portal_products` overrides bundled catalogue. Banner images are WebP data URIs in PostgreSQL, exposed through versioned image routes. Customer quotes/orders live in `records`; legacy inventory is scoped per customer. Server obtains Biteship rates and creates Midtrans Snap transactions. Signed notifications are verified again through Midtrans. Hostinger deploys the main branch.

No payment, shipping, database or auth change is safe without following those dependencies through quote → order → payment → cancellation. Existing uploaded artwork is retained. No fabricated prices, transactions, or performance numbers.

## Audit baseline / limitations

- `npm audit --omit=dev`: 8 affected packages (1 critical, 7 high). This is a package advisory count, not a claim that every advisory is exploitable here.
- Last measured banner manifest before this audit: 1,478 bytes HTTP, versus 1,156,042 before the earlier fix. Image binary remains separate.
- Browser viewport checks, Lighthouse, request timing and security negative cases are recorded in the QA result, not assumed from static code.
- Real money payment, courier booking and external customer messages are excluded from test execution. Server-side payment verification is reviewed and pure transition tests cover reordered/duplicate statuses.
- Security baseline: https://top10.owasp.org/2025/ and https://github.com/vercel/next.js/security/advisories .

## Final implementation and QC — 23 September 2026

- Latest visual direction supersedes the earlier proposed extra text hero: retain the administrator's four uploaded banners, full image/contain, no extra promotional copy layer. Desktop height is 220–300 px; mobile stays compact. Six category illustrations reuse the user-provided reference as one optimized WebP sprite. Product cards have distinct pastel media frames and full-width cart buttons. Price, stock and uploaded media remain database-driven; reference claims were not copied into product data.
- Shared bounded PostgreSQL pool, schema readiness check, deadline/error states, parallel catalogue/profile loads, route-specific dynamic imports, versioned banner images and matching logout cookie attributes implemented.
- Global stock reservation now runs with order creation in a transaction. Order/payment lock ordering, duplicate payment attempts, duplicate/reordered webhooks and stock return are guarded. Late paid-after-release events are explicitly marked for review.
- Runtime dependency audit: 8 advisories before (1 critical, 7 high), 0 after. Four moderate development-tool advisories remain; no force upgrade was applied.
- Nine existing product originals optimized from 7,916,883 to 295,674 bytes (96.3% smaller); logo 658,040 to 21,598 bytes. Legacy product sprite sheets also converted to WebP. Custom admin uploads are preserved.
- Production build and TypeScript passed. Shopping validation suite passed (38 provinces, village/postcode consistency, address tampering, phone, splicer prices, stock limits, payment status transitions, route allowlist). Transactional stock test passed against a temporary table and rolled back, without touching production stock.
- HTTP regression passed: unauthorized admin/sales/orders/payment access; unauthorized product edit; hostile Origin; invalid webhook; disabled simulation; four banner records/eight image variants; 404, robots and security headers. Admin login measured 680 ms and overview 361 ms on the local production build with live database; logout revokes the session. These are individual measurements, not an SLA.
- Final homepage tested at widths 320, 360, 375, 390, 414, 768, 1024, 1280, 1440, 1920: no horizontal document overflow. Desktop category top is 590 px at 1440/1920; mobile category top 343–390 px. Desktop/mobile screenshots visually inspected. Guest add-to-cart, quantity increment/decrement, recalculated totals, optional referral and advance to sign-in/shipping verified in browser.
- Lighthouse mobile emulation on local production build: Performance 76, Accessibility 96, SEO 100; LCP 5.2 s under throttling. Earlier audit within this batch was 76/90/100. Public-site Lighthouse baseline returned HTTP 403, so no valid before/after production comparison is claimed. JSON reports are outside repository in D:/KLIKFIBER.ID/audit-results.

## Remaining limitations / follow-up

- Performance is improved but not a perfect score: client-discovered banner requests and JavaScript startup remain opportunities. Public network/Hostinger timings may differ from localhost.
- Existing repository lint debt remains; lint is not a passing gate for this release. Build, typecheck and focused regression tests pass.
- No real-money payment, courier booking or end-to-end Google customer authentication was performed. Provider transitions were tested locally; invalid webhook/auth cases were checked over HTTP. Full payment and shipping sandbox certification still needs dedicated test credentials and an authenticated test buyer.
- Automatic recovery of a provider request with an unknown outcome and global cleanup of abandoned unpaid reservations need further operational work. Current expiry cleanup is request-driven; do not claim scheduled cleanup exists.
- CSP is deliberately limited to compatible object/base/frame restrictions; strict script-source rollout and dynamic Product structured data remain follow-up work. This is a bounded audit, not a guarantee of zero vulnerabilities.
- Publish all changes in one GitHub push and allow one Hostinger deployment; do not repeatedly rebuild on the hosting service.
